## Contributing

Thanks for your interest in contributing. This is an open project and input is welcome — bug reports, ideas, and pull requests all help.

Here's how to make a contribution land smoothly:

---

### 1. Open an issue first

For anything beyond a trivial fix, open an issue before writing code. It lets us agree on the approach and avoids wasted effort. Use the templates under **Issues → New issue**:

- **Log a Bug** — something is broken or documented incorrectly
- **Request a Feature** — a capability you'd like to see

---

### 2. Pull requests

1. Fork the repo
2. Create a branch off `main` (or `dev` if the repo uses one)
3. Make your change, keeping it focused — one concern per PR
4. **Sign your commits** — this repo requires signed commits (`git commit -S`)
5. Open a PR with a short description of *what* changed and *why*

A PR needs at least one approving review before merge. Keep history linear (rebase, don't merge-commit your branch).

---

### 3. Ground rules

- Be respectful and constructive.
- Don't commit secrets — the `.gitignore` blocks common credential patterns and push protection is enabled, but stay alert.
- Small, well-described changes get reviewed fastest.
